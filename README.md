# Sonos Discord Presence

A Windows tray app that reads what's currently playing on a Sonos speaker
and shows it as your Discord Rich Presence — track title, artist/album,
and elapsed time, with source-aware formatting for streaming services,
internet radio, local library files, and line-in.

Everything runs locally: it talks to Sonos over your LAN and to Discord
over its local IPC pipe. No server, no cloud component, no telemetry.

## How it works

| Module | Responsibility |
|---|---|
| `sonos_discord_presence/config.py` | Reads/writes `%APPDATA%\SonosDiscordPresence\config.json` |
| `sonos_discord_presence/sonos_client.py` | Discovers Sonos speakers, polls the tracked one in a background thread |
| `sonos_discord_presence/metadata.py` | Classifies the track's URI scheme and normalizes title/artist/album so Discord never shows a blank field |
| `sonos_discord_presence/discord_rpc.py` | Wraps `pypresence`, connects/reconnects to Discord's IPC pipe, falls back to a generic art asset when Sonos's album art URL is LAN-only |
| `sonos_discord_presence/tray.py` + `dialogs.py` | System tray icon/menu and the small tkinter dialogs it opens |
| `sonos_discord_presence/startup.py` | Adds/removes the per-user "run at Windows startup" registry entry |
| `sonos_discord_presence/app.py` | Wires all of the above together, including the idle grace period before clearing presence |

## 1. Create a Discord Application (Client ID)

Rich Presence requires a Discord Application ID, free to create:

1. Go to the [Discord Developer Portal](https://discord.com/developers/applications).
2. Click **New Application**, give it a name (e.g. "Sonos").
3. Copy the **Application ID** from the General Information page — this is
   your Client ID.
4. Optional but recommended: open **Rich Presence → Art Assets** and
   upload an image with the asset key `logo`. The app uses this as the
   large image whenever Sonos's album art URL isn't reachable from
   Discord's client (e.g. local library tracks, some radio stations).
   `assets/logo.png` (generated by `assets/generate_icons.py`) works as a
   placeholder.
5. Enter this Client ID when the app asks for it on first run (or later
   via the tray menu's **Settings**).

## 2. Run from source

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python assets\generate_icons.py   # creates tray/app icons if you haven't already
python main.py
```

On first run you'll be asked for your Discord Client ID, then shown a
list of Sonos speakers found on your network to pick from. Both choices
are saved to `%APPDATA%\SonosDiscordPresence\config.json`.

## 3. Build the standalone exe (PyInstaller)

```powershell
pip install -r requirements.txt
python build\build.py
```

This runs `pyinstaller build\build.spec` (`--windowed`, one-file, icon set
to `assets\icon.ico`) and produces `dist\SonosDiscordPresence.exe` — a
single file with no console window.

## 4. Build the installer (Inno Setup)

Install [Inno Setup](https://jrsoftware.org/isinfo.php), then either open
`installer\installer.iss` in the Inno Setup Compiler and click **Compile**,
or from the command line:

```powershell
iscc installer\installer.iss
```

This produces `dist\installer\SonosDiscordPresence-Setup.exe`.

**Install location:** the installer installs to `%LOCALAPPDATA%\SonosDiscordPresence`
per-user, with `PrivilegesRequired=lowest` — no admin/UAC prompt. This is
a single-user tray utility with no shared-machine use case, and the
"Start with Windows" feature writes to `HKCU\...\Run` (also
admin-free), so a `Program Files` install would only add elevation
friction with no corresponding benefit.

### CI: automated builds and releases

`.github/workflows/release.yml` builds the exe and installer on
`windows-latest` and publishes them to a GitHub Release. It runs on:

- **Pushing a tag** matching `v*.*.*` (e.g. `git tag v2.0.1 && git push origin v2.0.1`).
- **Manual dispatch** from the Actions tab, where you supply the release tag to use.

Either way it produces a release with `SonosDiscordPresence.exe` (the raw
onefile build) and `SonosDiscordPresence-Setup.exe` (the installer, built
with its version set to match the release tag) attached as assets.

The installer also:
- Adds a Start Menu shortcut (and an uninstall shortcut).
- Offers a **"Launch automatically when Windows starts"** checkbox, which
  adds a `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` entry (the
  same key the tray app's own "Start with Windows" toggle manages, so
  either one stays in sync).
- On uninstall, removes the exe, Start Menu shortcuts, and the startup
  registry entry automatically, and **asks** before deleting your saved
  config (`%APPDATA%\SonosDiscordPresence`) — it's never deleted silently.

## Using the app

The app runs minimized to the system tray. Right-click the icon for:

- **Status** — shows what's currently detected (`Playing: <track>`,
  `Paused: <track>`, `Idle`, or an error state).
- **Select Sonos Speaker** — re-run discovery and switch which
  speaker/group is tracked.
- **Settings...** — change the Discord Client ID, poll interval, and
  (optionally) Spotify Developer credentials for real album art.
- **Start with Windows** — toggles the startup registry entry.
- **Quit**.

The tray icon itself changes to a red variant when something's wrong
(Discord not running, speaker unreachable) so you can tell at a glance
without opening the menu.

### Real album art for Spotify (optional)

Sonos always serves album art from the speaker's own local address
(`http://<speaker-ip>:1400/getaa?...`), even for Spotify tracks — that URL
is LAN-only, so Discord's client can never fetch it, and the app falls
back to the generic uploaded `logo` asset instead.

To show the actual album art for Spotify tracks, create a free app at the
[Spotify Developer Dashboard](https://developer.spotify.com/dashboard),
copy its **Client ID** and **Client Secret**, and enter them via the tray
menu's **Settings...** (leave blank to leave the feature off — no Spotify
calls happen unless both are set). The app then looks up each Spotify
track's real artwork by title/artist over Spotify's public catalog search
(no Spotify login required) and uses that URL directly instead of Sonos's
local one. This only applies to Spotify; other streaming services (Apple
Music, Amazon Music, etc.) still fall back to the generic asset, since
they don't have an equivalent free public lookup.

### Real album art for SoundCloud (optional, requires existing credentials)

Same underlying problem as Spotify, but SoundCloud closed public API
registration years ago, so there's no "create a free app" path for new
credentials. This only does anything if you already hold a client_id for
SoundCloud's `api-v2` endpoint (the one their own web player uses — not
an officially documented third-party API, so treat this as best-effort
and something that can break if SoundCloud changes it). If you have one,
enter it via **Settings...** (leave blank to leave it off).

Sonos doesn't give SoundCloud its own URI scheme the way it does for
Spotify, so SoundCloud tracks are only distinguishable as "some generic
streaming service" — this lookup is tried for any non-Spotify streaming
track when a client_id is configured, and only accepts a search result
whose title (and artist, if known) actually matches what Sonos reported,
to avoid attaching the wrong art to some other service's track.

## Troubleshooting

**Discord isn't detected / presence never appears**
- Make sure the Discord desktop client (not just the browser) is running
  and you're logged in.
- Rich Presence must be enabled: Discord → User Settings → Activity
  Privacy → "Display current activity as a status message".
- The app retries the Discord connection every 15 seconds in the
  background — you don't need to restart it once Discord is up. Tray
  status/tooltip will show "(Discord not connected)" until it connects.

**No Sonos speaker found**
- Confirm the PC and the Sonos speaker are on the same subnet/VLAN — the
  app uses SSDP discovery, which doesn't cross most VLAN or guest-network
  boundaries.
- Check Windows Firewall isn't blocking Python/the exe from UDP
  multicast/discovery traffic.
- Use **Select Sonos Speaker** from the tray menu to re-run discovery
  once the network issue is fixed; no restart needed.

**Presence shows "Unknown Track" / "Unknown Artist"**
- Some sources (local NAS files with poor tagging, certain radio
  stations) genuinely don't give Sonos better metadata than that — this
  is the intentional fallback rather than showing a blank field.

**Presence doesn't clear when I pause**
- By design: pausing/stopping waits `idle_grace_seconds` (default 12s,
  editable in `config.json`) before clearing, so brief pauses between
  tracks don't flicker the presence off and back on. It will clear after
  that grace period if playback doesn't resume.

**Where's the log file?**
- `%APPDATA%\SonosDiscordPresence\app.log` (rotated, last ~2MB kept).
